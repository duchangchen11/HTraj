# 行人索引排列敏感性：固定官方checkpoint诊断

## 设计与边界

使用Stage4已经成功运行的官方维护版ZARA2 `val_best.pth`，没有更新权重。选择协议A验证集按时间顺序前64窗口，235目标窗口，seed271828生成每窗口一个随机排列。包含N=2至7；没有按误差挑样本，没有采样轨迹，全部用K1高斯均值。

若 $P$ 为行人置换矩阵，历史输入置换为 $V'=VP^T$，图为 $A'=PAP^T$；forward后将输出沿行人维用逆排列恢复，最后加回原ID对应的最后观测位置。物理历史与图边不变，只有存储索引改变。人工测试检查矩阵共轭、逆排列和恢复，避免把错误恢复当成模型问题。

该诊断是固定checkpoint推理干预；不是从头训练对照，也不是新的验证集、跨场景泛化或置换增强效果证明。官方权重可能上游接触过ETH训练材料，但本轮不读ETH轨迹或评价成绩。

## 定位计算模块

将每个模块输出逆置换后，与原始运行作绝对值比较，不能将不同层的feature单位当成米。

| 模块 | 最大feature绝对差 |
| --- | ---: |
| st_gcns.0.gcn | 1.1921e-7 |
| st_gcns.0（含时间卷积/BN/residual） | 2.3842e-7 |
| tpcnns.0 | 1.907375 |
| tpcnns.1 | 0.637213 |
| tpcnns.2 | 0.961642 |
| tpcnns.3 | 1.048433 |
| tpcnn_ouput | 1.319965 |

ST-GCN差异符合重排求和的浮点误差；显著差异首次出现于 **tpcnns.0的3×3卷积**。该张量轴为 `[B,8,5,N]`，核宽3直接混合相邻存储索引的行人，既不是物理邻居集合，也不保证任意节点排列等变。后续同类卷积继续传播差异。模型中的 `.view` 保持最后节点维，不是本次第一个破坏等变的位置。

因此仅把社会图改成单位矩阵不能得到真正NoSocial，自动Jacobian测试也验证单位图下其他行人仍影响目标输出。训练态原BN还会共享当前节点统计，是另一条需要隔离的跨人路径；本次checkpoint在eval，BN本身不构成这一数值差异的解释。

## 可验证结论与后续限制

已证实：**这一个官方维护版checkpoint在固定非ETH样本上不具备节点排列等变性，且定位到TXP-CNN节点卷积。** 未证实：这是所有性能问题的原因、去掉它一定提升预测、社会图无价值、随机排列训练可改善。冻结上游源文件未修改。

NoSocial将节点卷积改为单人轴卷积、隔离BN与图路径，人工train/eval输入Jacobian对其他节点为0且具备排列一致性；它仍需独立训练后才能比较性能。修改节点维计算的思想本身不是新创新。任何后续结构研究先排除索引伪关系，再问合法社会图是否有独立收益。
